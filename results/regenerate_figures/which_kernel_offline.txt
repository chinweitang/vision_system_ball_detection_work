    stripped source; zero hits for "compute_mask"/"rect"/"RECT").
    => uses stock detector_core.compute_mask => CLOSE KERNEL = ELLIPSE

  13_generate_rect_close_detections_csv.py
    l.38  import detector_core as dc
    l.39  from compute_mask_rect_close_variant import compute_mask_rect_close
    l.42  dc.compute_mask = compute_mask_rect_close      <-- MONKEYPATCH
    l.44  STAGE = "12_rect_close_kernel"
    l.48  DETECTIONS_ROOT = DETECTOR_TUNING_DIR / "detections" / STAGE
    l.90  raw = dc.run_detection(...)

  compute_mask_rect_close_variant.py::compute_mask_rect_close
    l.39 open_k  = getStructuringElement(cv2.MORPH_ELLIPSE, ...)   (open unchanged)
    l.42 close_k = getStructuringElement(cv2.MORPH_RECT, ...)      <-- RECT close

  Why the patch takes effect: detector_core._detect_in_pair (l.66) calls
  the bare global name compute_mask, resolved in detector_core's module
  namespace at call time, so rebinding dc.compute_mask does redirect it.

On-disk, results/detector_tuning/detections/ contains exactly these two
stages: "03_stride1_thresh16_openk3_area30_circ0.3" (ELLIPSE, from 11)
and "12_rect_close_kernel" (RECT, from 13).
NOTE: the "03_..." stage name encodes openk3 but NOT the close kernel -
the name alone is not evidence; the generator's source is.
